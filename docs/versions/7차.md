### LEVEL 1 · 실제 동작을 따라 읽기

성장 속도·카메라·첫 입력 타이머와 물리 복원을 정리했습니다.

성장 단계별 이동 속도·카메라 전환과 첫 입력에서 시작하는 타이머를 적용합니다. 가까운 목표 최대 5개를 0.1초마다 탐색합니다.

ReferencePhysicsSettings와 바닥·그룹 충돌체·마찰·초기 안정화·프레임당 활성화를 보완합니다. 강체 풀 384개 상한과 원격 대체 낙하는 아직 남고 수집은 bounds 겹침 래치를 사용합니다.

Verification에는 사건별 캐시·Gradle 복구 도구가 있습니다. 실제 캐시 삭제·과거 환경 쓰기가 포함되므로 일반 실행 절차로 호출하지 않습니다.

CLI는 명령어와 옵션을 입력해 프로그램을 실행하는 방식입니다. APK는 안드로이드 기기에 설치하는 앱 패키지입니다.

입력 — 터치·조이스틱 입력, 해당 차수 레벨·물체·에셋

처리 — 입력 이동 → 물체 흡수·폭탄 판정 → 미션·성장 → 종료 상태

출력 — 게임 화면·미션/시간 상태·로컬 진행 기록

### LEVEL 1 · 준비하고 확인할 것

해당 차수의 Assets·씬·Packages·ProjectSettings를 같은 버전으로 준비한 Unity 프로젝트가 필요합니다. 공개 소스 보관본은 완전한 씬·모델·텍스처·프로젝트 설정을 모두 포함하지 않습니다. 후기 환경은 Unity 6000.3.6f1과 Android Build Support를 사용합니다.

완전한 같은 차수 Unity 프로젝트에서 씬을 열어 Editor 플레이를 확인하고 대상 플랫폼으로 빌드합니다. C# 파일 복사만으로 APK가 생성되지는 않습니다. 캐시 삭제·원래 사건의 복구 도구는 일반 실행 절차로 사용하지 않습니다.

### LEVEL 1 · 결과와 주의할 범위

미션 진행·수집 성장·남은 시간·승패를 구분합니다. 카탈로그와 실제 자산 수를 화면의 고정 홍보 문구로 대신하지 않습니다. 로컬 저장은 서버 동기화나 실제 결제 기록이 아닙니다.

**상황:** Unity 프로젝트로 바로 열리지 않음

**확인할 내용:** 해당 차수의 Packages·ProjectSettings·씬과 외부 자산을 준비합니다.

**상황:** 다른 차수 게임이 생성됨

**확인할 내용:** 초기 HoleItBuilder와 후기 ReferenceBuilder의 차수를 확인합니다. 제작 도구는 기존 자산·설정을 덮어쓸 수 있습니다.

**상황:** 모델·충돌체가 누락됨

**확인할 내용:** 선택 차수의 카탈로그·메시·프리팹 조합을 확인합니다.


### LEVEL 1 · 도구 옵션과 결과 해석

게임을 실행하는 도구와 검사 기록을 모으는 도구는 다릅니다. `merge_test_results.py`의 **진단 시험(`--diagnostic`)은 문제를 찾기 위한 별도 기록이며 회귀검사 통과 범위에 더하지 않습니다.** 기준 검사는 기본75개(`EXPECTED_BASE_COUNT=75`)이고 기본 입력은 `Tests-second.xml`입니다. 추가·대체 XML 실행은 오래된 것부터 넣습니다. `--final`은 제공한 모든 실행 파일이 최종본임을 사용자가 명시 확인하는 선언이지 시험을 새로 실행하거나 실패를 성공으로 바꾸는 기능이 아닙니다. `--source-note`에는 확인한 검사 도구 변경이나 실행 한계를 기록합니다.

문자·화면 자원 내보내기는 게임 플레이가 아니라 **참조 자원에서 필요한 표현 정보를 준비하는 개발 도구**입니다. Typography의 `--reference-dir`는 필수 입력이고 `--unitypy-path`는 UnityPy 환경 경로를 지정하는 옵션입니다. UI 프리셋 도구가 있는 차수에서는 `--audit`·`--reference-dir`·`--unitypy-path`가 모두 필수입니다. 두 도구의 필수 조건이 같다고 가정하지 않습니다.

빌드 자료 명세의 `--release`는 Path이며 기본은 스크립트의 상위 차수 경로, `--apk`는 APK Path 입력입니다. 원래 배포·APK·도구 경로와 부작용을 확인하며 캐시 복구를 일반 확인 명령으로 실행하지 않습니다.

필수 UI 사례는 찾기 표시가 overlay·camera canvas 모두에서 유지되었다가 정상 만료되는지, 원래 폭탄 안내의 밝은 패널·어두운 글자가 보존되는지입니다. 집계 출력 Tests.xml·Tests.log·TestProvenance.json에서 결과와 출처를 함께 읽습니다.

### LEVEL 2 · 도구 옵션과 결과 해석

검사 집계의 개념은 **기준 회귀·대체/추가 실행·진단·출처 설명·최종 확인**으로 나뉩니다. 기본 `--base=Tests-second.xml`과 기준75개를 바탕으로 완료 XML을 오래된 순서로 읽고, `--diagnostic`은 별도 설명만 하며 회귀 coverage에 합산하지 않습니다. `--source-note`는 확인된 harness 변경·run 한계를 남기고 `--final`은 모든 제공 run 파일의 최종 여부를 명시 확인합니다. 따라서 진단 파일이 늘었다고 제품 회귀 범위가 늘었다고 해석할 수 없습니다.

참조 데이터 위치와 추출 도구의 Python 환경을 분리해 읽습니다. Typography는 **필수 reference-dir와 unitypy-path 옵션**, UI 프리셋은 **audit·reference-dir·unitypy-path 모두 필수**라는 계약입니다. 이 도구를 호출하는 것과 씬·모델·프로젝트 설정이 모두 준비되는 것은 다릅니다.

빌드 자료 명세의 `--release`는 Path이며 기본은 스크립트의 상위 차수 경로, `--apk`는 APK Path 입력입니다. 원래 배포·APK·도구 경로와 부작용을 확인하며 캐시 복구를 일반 확인 명령으로 실행하지 않습니다.

필수 UI 사례는 찾기 표시가 overlay·camera canvas 모두에서 유지되었다가 정상 만료되는지, 원래 폭탄 안내의 밝은 패널·어두운 글자가 보존되는지입니다. 집계 출력 Tests.xml·Tests.log·TestProvenance.json에서 결과와 출처를 함께 읽습니다.

### LEVEL 4 · 도구 옵션과 결과 해석

집계 설계는 **회귀 coverage와 진단 provenance를 분리**합니다. `EXPECTED_BASE_COUNT=75`, 기본 `--base=Tests-second.xml`, 오래된 순서의 완료 overlays를 기준으로 해석하며 append 옵션인 `--diagnostic`은 coverage에서 제외합니다. `--source-note`는 검증된 harness 변경·run 제한을 provenance와 summary에 남깁니다. store_true `--final`은 모든 제공 run 파일의 최종본 확인을 명시하는 계약이며 정적 선언으로 회귀시험 실행이나 성공을 대체하지 않습니다. Audit·Verification의 대응 구현과 main·인자 정의를 함께 검토합니다.

자원 준비 도구의 입력 계약을 런타임과 분리합니다. Typography의 reference-dir required=True,unitypy-path의 별도 정의와 UI 프리셋의 audit/reference-dir/unitypy-path required=True를 대조합니다. 필수 경로·원래 참조 데이터·출력 부작용을 검토하며 다른 도구의 기본값을 이식하지 않습니다.

빌드 자료 명세의 `--release`는 Path이며 기본은 스크립트의 상위 차수 경로, `--apk`는 APK Path 입력입니다. 원래 배포·APK·도구 경로와 부작용을 확인하며 캐시 복구를 일반 확인 명령으로 실행하지 않습니다.

필수 UI 사례는 찾기 표시가 overlay·camera canvas 모두에서 유지되었다가 정상 만료되는지, 원래 폭탄 안내의 밝은 패널·어두운 글자가 보존되는지입니다. 집계 출력 Tests.xml·Tests.log·TestProvenance.json에서 결과와 출처를 함께 읽습니다.

<a name="-목적과-이-차수의-역할"></a>
## 목적과 이 차수의 역할

성장에 따른 이동·카메라 변화와 첫 입력 타이머를 연결하고 물리 설정을 보완한 자료입니다.

<a name="features"></a>

<a name="-핵심-기능과-보존-범위"></a>
## 핵심 기능과 보존 범위

**항목:** 1

**이 차수에서 확인할 내용:** 성장 속도·카메라·첫 입력 타이머와 물리 복원을 정리했습니다.

**항목:** 2

**이 차수에서 확인할 내용:** 성장 단계별 이동 속도·카메라 전환과 첫 입력에서 시작하는 타이머를 적용합니다. 가까운 목표 최대 5개를 0.1초마다 탐색합니다.

**항목:** 3

**이 차수에서 확인할 내용:** ReferencePhysicsSettings와 바닥·그룹 충돌체·마찰·초기 안정화·프레임당 활성화를 보완합니다. 강체 풀 384개 상한과 원격 대체 낙하는 아직 남고 수집은 bounds 겹침 래치를 사용합니다.

**항목:** 4

**이 차수에서 확인할 내용:** Verification에는 사건별 캐시·Gradle 복구 도구가 있습니다. 실제 캐시 삭제·과거 환경 쓰기가 포함되므로 일반 실행 절차로 호출하지 않습니다.

<a name="usage"></a>

<a name="️-화면과-사용-흐름"></a>
## 화면과 사용 흐름

1. ReferenceCatalog와 이 차수 모델·배치·UI 리소스를 함께 준비합니다.
2. 해당 차수 ReferenceBuilder 계열 도구와 생성 씬을 확인한 뒤 플레이합니다.
3. 조이스틱으로 홀을 이동하고 목표·성장·폭탄·남은 시간을 읽습니다.
4. 종료 후 로컬 진행과, 구현되어 있다면 상점·하트·출석 상태를 확인합니다.

## 설치 환경과 실행·사용법

해당 차수의 Assets·씬·Packages·ProjectSettings를 같은 버전으로 준비한 Unity 프로젝트가 필요합니다. 공개 소스 보관본은 완전한 씬·모델·텍스처·프로젝트 설정을 모두 포함하지 않습니다. 후기 환경은 Unity 6000.3.6f1과 Android Build Support를 사용합니다.

완전한 같은 차수 Unity 프로젝트에서 씬을 열어 Editor 플레이를 확인하고 대상 플랫폼으로 빌드합니다. C# 파일 복사만으로 APK가 생성되지는 않습니다. 캐시 삭제·원래 사건의 복구 도구는 일반 실행 절차로 사용하지 않습니다.

## 처리 결과와 출력 읽기

미션 진행·수집 성장·남은 시간·승패를 구분합니다. 카탈로그와 실제 자산 수를 화면의 고정 홍보 문구로 대신하지 않습니다. 로컬 저장은 서버 동기화나 실제 결제 기록이 아닙니다.

<a name="️-제약과-문제-해결"></a>
## 제약과 문제 해결

**상황:** Unity 프로젝트로 바로 열리지 않음

**확인할 내용:** 해당 차수의 Packages·ProjectSettings·씬과 외부 자산을 준비합니다.

**상황:** 다른 차수 게임이 생성됨

**확인할 내용:** 초기 HoleItBuilder와 후기 ReferenceBuilder의 차수를 확인합니다. 제작 도구는 기존 자산·설정을 덮어쓸 수 있습니다.

**상황:** 모델·충돌체가 누락됨

**확인할 내용:** 선택 차수의 카탈로그·메시·프리팹 조합을 확인합니다.

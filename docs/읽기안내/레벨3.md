## LEVEL 3 · 프로젝트 소개와 읽는 방법

이 수준은 같은 차수의 Unity 프로젝트를 준비하고 플레이·빌드 결과를 확인하려는 독자를 위한 안내입니다. **실행 가능한 전체 프로젝트가 있는지 확인하는 것이 첫 단계**이며 공개 C# 보관본만으로 설치 성공을 가정하지 않습니다.

## LEVEL 3 · 실제 기능과 동작 범위

확인 대상은 입력 이동, 흡수 판정, 미션·성장, 타이머와 종료, 일시정지·재개, 프로필·출석 저장입니다. 8차라면 실제 진입·이탈 트리거, 0.3초 뒤 성장 적용, 열린 원형 게이지와 수집 뒤 렌더·승리 뒤 물리 갱신을 해당 코드와 대조합니다. 9차라면 필수 참조 검사와 세션별 보상 소유권을 읽는 범위이며 완전한 플레이 검증으로 바꾸지 않습니다.

## LEVEL 3 · 입력에서 처리와 출력까지

씬에 연결한 레벨·모델·충돌 메시·배치 메타데이터와 입력이 게임을 구동합니다. 오류가 나면 스크립트만 보지 말고 직렬화 참조·카탈로그·글꼴·TMP 프리셋의 누락 여부를 확인합니다. 출력 검토에서는 미션 목표 수와 성장 포인트, 보유 재화와 화면 문구를 각각 구분합니다.

## LEVEL 3 · 사용·실험 순서와 확인 방법

8차의 README.txt와 소스를 확인하고, Unity 6000.3.6f1·Android Build Support 및 같은 차수의 씬·Packages·ProjectSettings를 준비합니다. Editor 임포트·컴파일 → 프로젝트 테스트 → 플레이 → 대상 플랫폼 빌드 순으로 확인합니다. 제공된 Build-Android.ps1 진입점과 UnityPath는 아래 원문 명령 그대로 참고하되 실제 설치 경로를 확인합니다. 빌드 스크립트는 전체 에셋을 포함한 원본 패키지의 크기 조건도 검사합니다.

## LEVEL 3 · 결과와 한계를 해석하는 기준

성공 판정은 실행한 검사의 범위를 적어 남깁니다. 정적 검사는 C# 컴파일·PhysX 실행·실기기 성능을 대신하지 않습니다. QA 도구의 저장 상태 초기화·폭탄 배치·순간 이동·시간 가속은 별도 시험 상태에서 사용하고, 과거 PASS 집계를 현재 소스의 새 결과로 쓰지 않습니다. 출석 실패는 같은 로컬 날짜 수령 이력도 확인합니다.

## LEVEL 3 · 구현과 핵심 파일을 연결해 읽기

먼저 ReferenceGame.cs와 부분 클래스, ReferenceProfile.cs·ReferenceAttendance.cs를 같은 차수에서 엽니다. 수집 이벤트가 게임 소유자로 전달되는 경로와 성장 적용 시점을 확인한 뒤 실제 화면·저장 결과와 대조합니다. 아래 전체 근거의 문제 해결 표는 프로젝트 누락, Builder 불일치, Android 모듈 누락, 자산 참조 오류를 분리하므로 실패 원인을 한 종류로 재시도하지 않습니다.

## LEVEL 3 · 용어와 실수하기 쉬운 구분

Unity는 화면·장면·입력·물리를 함께 구성하는 게임 제작 환경입니다. 씬은 물체와 화면을 배치한 장면이고, 에셋은 모델·그림·소리 같은 자원입니다. 강체는 중력과 충돌 계산을 받는 물체, 충돌체는 부딪히는 범위를 뜻합니다. 트리거는 범위 진입·이탈을 알려 주는 감지 장치입니다. 객체 풀은 만들어 둔 물체를 다시 쓰는 방식이고, 프레임은 화면·게임을 갱신하는 한 번의 단위입니다.

**공개 코드 보관본과 완전한 Unity 실행 프로젝트는 다릅니다.** 초기 HoleItBuilder와 후속 ReferenceBuilder 계열을 섞지 않습니다. 로컬 코인·하트·출석은 서버 결제·계정 동기화가 아니며, 과거 캐시 삭제·Gradle 복구 도구는 일반 플레이 절차로 실행하지 않습니다.

## LEVEL 3 · 항목별 자세한 풀이와 확인 지점

### LEVEL 3 · 두 구현 계열과 게임 상태

필수 씬 참조·성장표가 준비되었는지 확인하고 Loading→Title→Ready→Playing과 완료·시간 초과 경로를 점검합니다. Pause/Resume와 포커스 상실에서 입력·배율이 맞는지 확인하고, 세션이 다른 풀링 객체가 보상을 다시 주는지 코드 조건을 대조합니다.

[이 항목의 전체 조건·원문](#source-section-2)

### LEVEL 3 · 최신차수에서 달라진 점

ReferencePhysicsTrigger 진입·이탈, ReferenceGrowthProgress 지연 적용, ReferenceGrowthRing 표시와 수집 뒤 렌더·승리 뒤 물리 갱신을 같은 8차 자원으로 확인합니다. 9차는 제품 스크립트 부분본으로 따로 읽습니다.

[이 항목의 전체 조건·원문](#source-section-3)

[이 항목의 전체 조건·원문](#source-section-4)

[이 항목의 전체 조건·원문](#source-section-5)

## 두 구현 계열과 게임 상태

초기 제품 계열에서는 `GameManager`가 입력·미션·레벨·홀·UI 참조를 연결합니다. 후속 Reference 계열은 `ReferenceGame`의 부분 클래스로 게임·물리·레벨·화면을 나눕니다. 서로 다른 계열의 스크립트와 씬을 같은 시점 프로젝트처럼 섞지 않습니다. 보존된 8차 Reference 구현과 9차 제품 스크립트 8개는 자료 범위가 다릅니다.

제품 GameManager 코드의 상태 흐름은 다음과 같습니다.

- 시작: 필수 참조와 성장표 검사 후 Loading→Title→Ready→Playing으로 전환합니다.
- 수집과 종료: 소비한 물체의 점수·성장·미션을 반영합니다. 목표 완료는 Clearing→LevelClear, 시간 소진은 Failed로 이어집니다.
- 보상: SessionId와 보상 소유권 검사로 이전 세션의 풀링 객체가 중복 지급하는 경로를 막습니다.
- 일시정지: Pause는 시간 배율 0과 입력 중단, Resume는 배율 1과 Playing 복귀이며 포커스 상실도 일시정지합니다.

Reference 8차에서는 진입·이탈 트리거, 지연 성장, 열린 원형 게이지를 변경했습니다. 프레임당 25개 활성화와 성장 지연 0.3초는 처리 설정이며 실제 FPS나 전체 강체 수 제한을 뜻하지 않습니다.

프로필·재화·하트·출석은 로컬 게임 상태이며 서버 결제나 계정 동기화와 다릅니다.

실행에는 같은 차수의 Unity 씬·Packages·ProjectSettings·모델/텍스처·직렬화 참조가 필요합니다. 공개 C#만 있는 부분본은 코드 흐름과 비교를 읽는 자료입니다. Builder와 복구/캐시 도구는 자산을 바꿀 수 있으므로 일반 플레이 명령처럼 일괄 실행하지 않습니다. 각 차수의 카탈로그·물리·저장 클래스와 실제 전체 차이는 아래 독립 안내에서 이어집니다.

### 1차부터 8차까지 달라진 점

**차수:** 1차

**구현 변화:** 미션 최대 3개, 객체 풀, 레벨 기록과 타이머를 갖춘 수집 프로토타입. Transform 기반 끌기·낙하와 반지름 보간

**차수:** 2차

**구현 변화:** 쌓인 물체의 중력·깨우기와 월드 좌표 드래그, 폭탄 소비 실패, 폭탄 처리 중 승리 유예

**차수:** 3~4차

**구현 변화:** ReferenceCatalog 기반 모델·배치·목표, 최대 1,023개 단위 묶음 렌더링과 30레벨 상한. 3차 터치 중 조이스틱에서 4차 상시 표시로 변경

**차수:** 5차

**구현 변화:** 별도 LocalPhysics3D 장면과 강체 풀 384개, 비동기 로딩, 로컬 코인·하트·부스터 상점

**차수:** 6차

**구현 변화:** TMP 글꼴, 챌린지·3D 도감·31일 출석, 배치 장애물과 랜덤 폭탄

**차수:** 7차

**구현 변화:** 성장 단계별 속도·카메라 전환, 첫 입력부터 시작하는 타이머, 가까운 목표 최대 5개를 0.1초마다 탐색

**차수:** 8차

**구현 변화:** 모든 배치 물체의 강체·충돌체 유지, 실제 트리거 수집 이벤트, 지연 성장과 열린 원형 게이지, 전체 경계 상자를 이용한 시야 검사


8차의 프레임당 활성화 25개는 전체 강체 수 제한이 아닙니다. 7차까지 남아 있던 강체 풀 384개 제한과 일부 원격 물체의 대체 낙하를 8차의 동작으로 설명하지 않습니다. 초기 직교 카메라와 후기 원근 카메라, 1차 이동 속도 8과 7차 이후 기본 속도 2.6도 서로 다른 구현입니다.

### 성장·카메라·물리 구성

8차 `ReferenceGrowthProgress`는 수집 점수를 누적하고 0.3초 뒤 다음 성장 단계를 적용합니다. 진행 링은 128분할 메시로 그리며, `ReferencePhysicsTrigger`는 진입·이탈 이벤트를 게임 소유자에게 전달합니다.

**설정:** 물리 성장 단계 상한

**후속 Reference 코드 값:** 10

**설정:** 이동 속도

**후속 Reference 코드 값:** 시작 2.6, 단계당 0.442 증가, 부스트 계수 1.3

**설정:** 카메라 시야각

**후속 Reference 코드 값:** 25 → 44, 전환 0.3초

**설정:** 중력·물리 간격

**후속 Reference 코드 값:** 35, 0.02초

**설정:** 성장 표현

**후속 Reference 코드 값:** 0.3초 확대 후 0.15초 복원


일부 구현 주석은 참조한 원본 데이터와 RVA를 기록합니다. Android 빌드 스크립트의 500MB 조건은 전체 에셋을 포함한 패키지의 크기 검사입니다.

## 빠른 시작

1. `8차/Source/README.txt`와 사용할 차수의 구현을 먼저 확인합니다.

완전한 8차 프로젝트를 준비한 환경에서 제공된 빌드 진입점은 다음과 같습니다.

```powershell
cd "8차/Source"
.\Build-Android.ps1 -UnityPath "C:\Program Files\Unity\Hub\Editor\6000.3.6f1\Editor\Unity.exe"
```

빌드에는 소스 외에 해당 차수의 씬·에셋·프로젝트 설정이 필요합니다. 스크립트는 전체 에셋을 포함한 원본 패키지의 APK 크기 조건도 검사합니다.

<a name="-실행시험-범위"></a>
<a id="source-section-13"></a>
### 실행·시험 범위

Unity 컴파일과 플레이 검증, Android 빌드와 실제 기기 성능 평가는 각 실행 환경에서 수행합니다.

후기 실행에는 ReferenceCatalog와 모델·충돌 메시·배치/장애물 메타데이터, 스타일·음원·글꼴·TMP 텍스트 프리셋이 필요합니다. 화면의 `465레벨`·`1,010물체` 문구는 공개 사본의 실제 자산 수를 보증하지 않습니다. 일부 코드가 원본 데이터·배치를 참조하므로 모든 모델과 그림을 직접 제작한 것으로 설명하지 않습니다.

Windows 캡처·시험 도구에는 버튼 호출, 폭탄 배치, QA 저장 상태 초기화와 시험용 이동이 포함됩니다. 사용하는 차수의 도구를 확인하고 별도 시험 상태에서 실행해야 합니다. 정지 장면 180프레임 기록과 순간 이동·시간 가속을 사용한 기능 시험을 제공합니다. Android 성능과 일반 조이스틱 플레이는 별도로 평가합니다.

<a name="️-편집기시험복구-도구를-사용할-때"></a>
<a id="source-section-14"></a>
### 편집기·시험·복구 도구를 사용할 때

**도구 묶음:** Editor 제작 도구

**실제 동작과 준비 조건:** 메시·텍스처·프리팹·레벨·씬·프로젝트 설정을 생성하거나 덮어씁니다. 선택한 차수의 에셋과 함께 사용해야 합니다.

**도구 묶음:** 오프라인 정적 검사

**실제 동작과 준비 조건:** 설정·참조·메시·UI 계산 등을 확인하지만 C# 컴파일·PhysX·실제 기기 플레이까지 실행하는 검사는 아닙니다.

**도구 묶음:** 캠페인 시험

**실제 동작과 준비 조건:** 순간 이동·반복 탐색·시간 배속·reflection을 사용하는 경로가 있어 정상 조이스틱 조작 완주와 구분해야 합니다.

**도구 묶음:** 이전 캐시 정리

**실제 동작과 준비 조건:** `cleanup_editor_cache.ps1`은 별도 적용 스위치 없이 조건 확인 뒤 `Library`의 `Bee` 외 직계 항목을 삭제합니다. 일반적인 확인 명령으로 실행하면 안 됩니다.

**도구 묶음:** 후속 캐시 정리

**실제 동작과 준비 조건:** `cleanup_editor_cache-fresh2abi.ps1`은 기본 계획 출력, `-Apply`에서 명시한 캐시만 삭제하며 연결 경로와 후손을 검사합니다. 특정 원래 빌드 증거에 의존합니다.

**도구 묶음:** Gradle 복구·시험 집계

**실제 동작과 준비 조건:** 원래 경로·로그·빌드 증거에 결합된 도구입니다. 집계된 과거 PASS는 현재 소스의 새 전체 시험 성공을 뜻하지 않습니다.


[7차 검증 도구](../../7%EC%B0%A8/Verification)는 원래 사건의 복구용 자료를 포함합니다. `fresh2abi` 도구 역시 임의 환경에 바로 적용하는 범용 복구 프로그램이 아닙니다. 이 저장소를 정리하는 동안 캐시 삭제·Gradle 복구·Unity 시험을 실행하지 않았습니다.

3차 reference and implementation audit

Input supplied by user: Hole+it!_1.31.17_APKPure.xapk.
No original managed C# project was available. This release contains separately
implemented C# gameplay plus selected converted content from the supplied app.

Content retained
- First 30 entries of list_main_fall_back, including level IDs, target quantities,
  stage time budgets and bomb counts. Not the original application's entire campaign.
- 259 item models, material textures and their target icons.
- Authored positions, quantized rotations, scale and per-placement growth points.
- Authored playground tiles, background tiles and convex/straight border placements.
- Five available environment themes from the selected bundle (1, 2, 3, 8, 9).
- Original hole mesh/texture, goal cards, timer background, selected buttons,
  joystick sprites and growth progress sprites.
- Perspective camera FOV 46 and pitch 60 from the supplied gameplay scene.

Growth verification
The supplied ARMv7 native image's method metadata and a small set of instructions
were inspected with Il2CppDumper 6.7.46 and Capstone. This was read-only analysis.
The native image and recovered metadata are not shipped with this project.
- HoleSizeManager.UpdateHoleProgressValue at 0x19706F8 subtracts requiredAmount
  from scaleValue on a promotion, then requests the next tier.
- OnObjectEatenResponse at 0x1970DD0 adds objectSize to scaleValue.
- IncreaseHoleSize at 0x1970A84 uses start scale + actual tier * .25 and
  starting movement-controller radius + actual tier * .223.
- SetNextHoleSizeLevel at 0x1970ED4 caps the actual size tier at 10.
- GetNextHoleSizeIncreaseInfo at 0x1970474 selects the next tier's own cost.
- Costs from SizeInfos: 10,20,100,150,200,300,400,500,600,700.
- Thus cumulative point boundaries are 10,30,130,280,480,780,1180,1680,2280,2980.
- Physical size stops increasing after tier 10; displayed progress can continue.
- Per-placement manual-size values from the level's cisd strings are the point
  weights. They are distinct from the count used for collection objectives.
- Initial hole parent scale and movement-controller radius are both .7.

Separate implementation / remaining differences
- Lightweight support/fall simulation and mesh-based intake replace original
  rigidbody/mesh-collider simulation. Objects fall where swallowed and do not
  follow the hole. Exact rigidbody collisions and original easing are not restored.
- Joystick uses bounded velocity and releases immediately, as requested by user.
- Lighting/shaders, camera following/zoom and some UI layout are separately made.
- Source environment geometry and tile placement are retained, but five themes
  cycle by stage instead of reproducing the original theme-selection service.
- Bomb counts and introductory stage follow the data; bomb spawn coordinates are
  generated by this project. Original random bomb runtime is not reproduced.
- Four boosters unlock at 3/5/9/12 and are free once per attempt. Advertising,
  store, lives, seasonal events, online services and monetization are absent.
- Menus, results, sounds and progress persistence are this project's implementation.
- Typography intentionally uses bundled Nanum Gothic Bold per user preference.

Verification scope
The campaign sweep uses real intake, falling stacks, goals and growth, but moves
the hole directly between targets. It is not a human pacing or difficulty test.
The first-stage movement test separately uses bounded velocity without teleports.
Previews are captured from a Windows build of the same scene and runtime.
APK build/signature/metadata are checked. No Android device was connected, so
physical-device touch behavior, GPU performance and sustained FPS remain untested.
